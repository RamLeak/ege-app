## 2. Что за проект

Личное Android-приложение для подготовки к ЕГЭ по двум предметам (профильная математика, русский язык) с локальной базой задач и интеграцией Claude API для объяснений. Информатика **исключена осознанно** — её решать всё равно надо на компьютере, не в мобильной app.

**Источник данных:** sdamgia.ru (РешуЕГЭ) — там есть авторские решения и нормальные `<img>` для картинок. Запасной источник: открытый банк ФИПИ (если sdamgia заблокирует парсер).

**НЕ цели проекта:**
- Не для Google Play, не для других людей.
- Не для синхронизации между устройствами.
- Не для других предметов.
- Не социальная сеть и не платформа уроков (теории/курсов в app нет).

## 4. Архитектура верхнего уровня

```
┌─────────────────────────────────────────────────────────┐
│  Машина разработки (C:\Projects\ege-app\)                │
│                                                          │
│  parser/  (Python 3.12)                                  │
│    sdamgia.ru → cache/raw/ → JSONL + assets/             │
│                            ↓                             │
│                       build_db.py                        │
│                            ↓                             │
│                      corpus.db (SQLite)                  │
│                                                          │
│  android/  (Kotlin + Compose, после Фазы 1)              │
│    Room ← corpus.db (как Asset)                          │
│    Compose UI + MathJax WebView                          │
│    Ktor → Claude API (только онлайн)                     │
└─────────────────────────────────────────────────────────┘
                            ↓
                    signed APK → adb install
```

Два независимых подпроекта. Парсер делает разовые/инкрементальные сборки `corpus.db`. Android-приложение читает готовый файл как ассет.

## 5. Tech stack

| Слой | Технология | Почему |
|---|---|---|
| Парсер | Python 3.12 + httpx + selectolax | selectolax в 20-50× быстрее BeautifulSoup на больших корпусах |
| Запасной парсер | Playwright | Только если sdamgia включит Cloudflare-челлендж |
| Промежуточный формат | JSONL + `assets/` | Идемпотентность, легко перестроить БД, человекочитаемо |
| БД | SQLite + Room (на Android) | Embedded, файл, идеально для офлайн-first; FTS5 для поиска |
| Mobile UI | Kotlin + Jetpack Compose | Современный путь, проще XML для новичка |
| Рендер формул | MathJax 4 в WebView | sdamgia хранит формулы в **MathML** (не LaTeX) — KaTeX не подходит |
| AI | Claude API через Ktor HTTP | Один эндпоинт, SDK не нужен. Haiku 4.5 по умолчанию, Sonnet 4.7 по запросу |
| Разработка | Claude Code (max20) | Пишет почти весь код, пользователь направляет |

## 6. Фичи (10x-версия, согласовано)

**Базовые (MVP):**
- Иерархическая навигация: предмет → тип задания (№1..№19) → подвид → задача.
- Просмотр условия с MathJax-рендером и картинками.
- Поле ввода ответа, автопроверка для коротких ответов.
- Авторское решение по кнопке.

**10x-надстройки:**
- Главный экран = **Предиктор балла** (по таблице ФИПИ из реального прогресса).
- **Радар слабых мест** на главном экране — по **подвидам** КЭС, не по типам (см. страховку #2).
- **Streak** — счётчик дней подряд (≥10 задач в день).
- **Журнал ошибок** — все неверно решённые с возможностью перерешать.
- **Прогресс-бары** по предметам, типам, подвидам, пробникам.
- **Генератор варианта** — рандомно собирает по одной задаче каждого типа.
- **История пробников** с графиком тренда.
- **Импорт открытых вариантов КИМ ФИПИ** как «официальных пробников».
- **AI-кнопка** — Claude объясняет конкретное непонятное место (с кешем).
- **Spaced repetition по ошибкам-формулировкам** (не по задачам) — карточки типичных ловушек ЕГЭ через 1/3/7/14/30 дней.

## 9. Шесть страховок из premortem (обязательные)

Это не рекомендации, это **зашитые в архитектуру решения**.

1. **Радар по подвидам, не по типам.** Главный экран показывает ~50 секторов КЭС (тригонометрия, показательные, стереометрия, и т.д.), не 19 (по номерам задач). Минимум 15 решённых для окрашивания сектора, иначе серый «недостаточно данных». — *Закрывает: ложную уверенность из-за смещённой выборки.*

2. **AI-замок на первой попытке.** Кнопка «Спросить ИИ» disabled до первого пользовательского ответа на задачу (даже неправильного). UI: «Сначала попробуй — потом спрашивай». — *Закрывает: AI как эмоциональная замена решения.*

3. **Календарь пробников зашит в app.** 16 пробников за год, каждые 3 недели. Первый — через 4 недели после конца Фазы 5. Счётчик «дней до следующего пробника» на главном экране. — *Закрывает: «год — это вечность», горизонт расплывается.*

4. **Стресс-тест корпуса при сборке БД.** В конце Фазы 1: парсер скачивает 10 открытых вариантов КИМ ФИПИ, для каждой задачи проверяет покрытие в `corpus.db` через семантический поиск. Если совпадение <80% — добираем. — *Закрывает: устаревший/неполный банк.*

5. **Правило «50 задач в неделю».** В каждую неделю, в которой был хоть один git-коммит, в app должно быть решено минимум 50 задач. Меньше — код заморожен на следующую неделю. — *Закрывает: «sublime app, пустая голова».*

6. **Контрольная точка через 8 недель.** Конкретная дата в Google Calendar. Если решено <300 задач за 8 недель — переключение в pure-usage mode на месяц (никакого кода). — *Закрывает: медленную деградацию мотивации на длинном горизонте.*

## 10. Запасные планы (fallback)

- **sdamgia банит парсер** → переключение на ФИПИ (структура известна, файлы разведки в `parser/fipi-recon-archive/`) + добор решений через Claude API однократно (~$5).
- **Cloudflare-челлендж на sdamgia** → переход с httpx на Playwright (+2 дня).
- **MathJax-рендер слишком медленный в WebView** → кешируем SVG в БД при build_db, рендерим один раз.
- **Compose не идёт у Claude Code** → запасной план: HTML-вьюер на ноуте + использовать в браузере. Это не «крах проекта», это смещение MVP в другую сторону.
