## Цель Фазы 1

К концу фазы на диске должны лежать:

1. `parser/corpus.db` — SQLite БД со всеми задачами по двум предметам (математика профильная + русский язык), привязанные к иерархии **subject → type → subtype → problem**.
2. `parser/assets/` — все картинки задач (PNG/JPG/SVG), скачанные локально.
3. `parser/{math,russian}.jsonl` — промежуточный формат на случай пересборки БД.
4. `parser/kim-fipi/` — 10 открытых вариантов КИМ ФИПИ-2026 для стресс-теста.
5. `parser/coverage_report.md` — отчёт о покрытии корпуса по этим вариантам.
6. Простой HTML-вьюер `parser/view_corpus.html` для проверки в браузере (открывает первые 20 задач каждого предмета).

**Ориентир по объёму:** ~2-4 тыс. задач математики, ~1.5-3 тыс. задач русского. Может оказаться больше — это нормально.

**Ориентир по времени:** 4-5 рабочих дней.

## Stage 0 — Разведка sdamgia (1 день, обязательно)

**Цель:** понять, отдаёт ли sdamgia задачи простому httpx или нужен Playwright. Понять URL-структуру каталога заданий.

### Что делаешь

1. Создаёшь `parser/scrapers/sdamgia_recon.py` — аналог `fipi-recon-archive/fipi_recon2.py`, но для sdamgia.
2. Делаешь **минимально достаточное** количество запросов (не больше 10 за всю разведку):
   - Главная страница sdamgia.ru.
   - Страница каталога предметов.
   - Каталог заданий профильной математики (типы №1..№19).
   - Каталог по одному типу (например, №13).
   - Одна конкретная страница задачи.
   - То же для русского.
3. Сохраняешь сырой HTML в `parser/recon-sdamgia/` для последующего анализа.
4. Анализируешь и докладываешь мне:
   - Какие URL у sdamgia (точные шаблоны)?
   - Какие CSS-селекторы для: блока задачи, условия, картинок, ответа, авторского решения, темы КЭС?
   - Формулы — MathML или LaTeX (или то и другое)?
   - Картинки — обычные `<img src="">` или JS-вызовы?
   - Есть ли пагинация и какая?
   - Подгружается ли что-то по AJAX/JS, или всё в HTML сразу?
   - Reasoning: можем ли мы это парсить простым httpx?
5. **Останавливаешься и ждёшь моё «продолжай»**, прежде чем начинать Stage 1.

### Сценарии и реакции на разведке

| Что обнаружил | Действие |
|---|---|
| Чистый HTML, всё парсится httpx-ом | Продолжаем как планировали |
| Cloudflare-челлендж, JS-shield | Сообщи мне, я скажу переключаться на Playwright (+2 дня к плану) или Plan B (ФИПИ из архива) |
| HTTP 403 / 429 уже на 5 запросах | Сообщи мне, обсудим что делать (VPN / Plan B) |
| Сайт лежит / DNS не резолвится | Сообщи мне, попробуем позже |
| Логин/капча для доступа к задачам | Сообщи мне немедленно — это меняет план кардинально |

**Не пытайся обойти антибот-защиту без моего согласия.** Если что-то не работает — стоп, обсуждаем.

## Stage 1 — Парсер математики профильной (1.5 дня)

После моего «продолжай» по результатам разведки.

### Что делаешь

1. Создаёшь `parser/selectors.yaml` — все CSS-селекторы из разведки в одном файле.
2. Создаёшь модули:
   - `parser/pipeline/fetch.py` — httpx + retry + rate limit + idempotent кеш в `cache/raw/`.
   - `parser/pipeline/parse.py` — selectolax селекторы из yaml.
   - `parser/pipeline/normalize.py` — очистка HTML, обработка MathML, скачивание картинок в `assets/{sdamgia_id}/`.
   - `parser/pipeline/store.py` — writer в JSONL.
3. Создаёшь `parser/scrapers/math_profile.py` — обходчик для профильной математики по каталогу.
4. Стратегия обхода: **по типу заданий** (№1, №2, ..., №19), внутри типа — **по подвидам/темам КЭС**, чтобы знать категоризацию каждой задачи. Внутри подвида — пагинация.
5. **State.json** — после каждых 50 успешных задач сохранять чекпоинт.
6. **Rate limit** — 1 запрос в 1.5-2с + джиттер, как в `CLAUDE.md`.
7. **Логирование** — `parser/logs/scraper.log`, каждый запрос с timestamp, URL, статусом, размером.
8. **Smoke-тесты** — в `parser/tests/test_smoke.py` сохрани 5 эталонных задач (с разными типами: текстовая, с формулой, с картинкой) и тесты, которые проверяют, что парсер их корректно разбирает. **Гоняй до и после изменений** в `selectors.yaml`.

### Definition of done для Stage 1

- На диске `parser/math.jsonl` с всеми задачами математики.
- `parser/assets/` — все картинки скачаны.
- `state.json` валиден, можно дозапустить инкрементально.
- Smoke-тесты зелёные.
- `parser/logs/scraper.log` показывает соблюдение rate limit.
- Доклад мне: количество задач, размер JSONL, размер `assets/`, время прогона.

## Stage 3 — `build_db.py` → corpus.db (0.5 дня)

### Что делаешь

1. Создаёшь `parser/build_db.py` — читает `math.jsonl` + `russian.jsonl`, создаёт `corpus.db` по схеме из `CLAUDE.md`.
2. Заполняешь все таблицы: `subjects`, `problem_types`, `problem_subtypes`, `problems`, `solutions`, и пустые `user_progress`, `ai_conversations`, `error_atoms`, `mock_exams`, `daily_streak`.
3. Создаёшь FTS5-индекс `problems_fts` и наполняешь.
4. Делаешь простой `parser/view_corpus.html` — статичная HTML-страница со списком первых 20 задач из БД (через `sql.js` или генерация на этапе сборки). Это для моей визуальной проверки.

### Definition of done

- `corpus.db` весит ~50-200 MB (зависит от объёма).
- В `view_corpus.html` я вижу 20 задач с условиями, формулами, картинками — глазами проверяю что нормально.
- Доклад: счётчики по таблицам, размер БД.

## Stage 4 — Стресс-тест по КИМ ФИПИ (1 день)

Реализация **Safety Rule #4**.

### Что делаешь

1. Скачиваешь с `fipi.ru` 10 открытых вариантов КИМ ЕГЭ-2026 по математике и русскому (поищи прямые ссылки на PDF/Word/архив).
2. Кладёшь в `parser/kim-fipi/`.
3. Извлекаешь задачи из этих вариантов (PDF/Word парсинг — pdfplumber или python-docx).
4. Для каждой задачи из КИМ проверяешь покрытие в `corpus.db`:
   - Сначала FTS-поиск по статистически значимым словам условия.
   - Если не нашлось точно — Claude API на похожесть (Haiku, разово на покрытие — пара $0.05).
5. Считаешь процент покрытия по предметам.
6. Создаёшь `parser/coverage_report.md` — отчёт «по варианту 1 покрыто 18/19 задач (95%), по варианту 2 — 16/19 (84%) ...». В конце средний процент.

### Definition of done

- Покрытие ≥80% по обоим предметам → ✅ Stage 4 пройден.
- Покрытие <80% → **доложи мне немедленно**, обсудим что добирать (возможно, sdamgia не покрывает какие-то типы — тогда план B).
